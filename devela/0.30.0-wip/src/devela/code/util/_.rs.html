7//!
8//! This module collects small, cross-cutting facilities for authoring,
9//! checking, inspecting, and transforming Rust code.
10//!
11//! [`assert`][mod@assert] checks assumptions, [`cfg`][mod@cfg] controls compilation,
12//! and [`debug`] assists diagnostics. [`synth`] constructs and composes Rust code,
13//! while [`token`] operates on the token, fragment, identifier,
14//! and literal material from which macros work.
15//!
16//! Facilities with a clearer domain or semantic home belong there instead;
17//! `util` is not a general catch-all namespace.
18//
19// # Implementation notes
20//
21// Several declarative macros are defined hidden with a `·` suffix and
22// publicly re-exported without it, allowing them to remain importable
23// from the crate's flattened surface. E.g. `capture_last!`, `is!`, `whilst!`.
24// See: https://github.com/rust-lang/rust/pull/52234#issuecomment-976702997
25//
26// # Warning regarding macro expansion
27//
28// Some attributes (#[doc = …], #[rustfmt::skip], and other tooling-related ones) cause the
29// compiler to inspect or expand tokens earlier than normal, before the crate's macro resolution
30// graph is fully fixed. At that point, macros that are only introduced indirectly (for example
31// via helper macros, exported macros, or re-exports) may not yet be visible, even if they would
32// exist after full expansion. Because macro_rules! resolution depends on phase ordering, this
33// can lead to "resolution is stuck" errors where the compiler cannot prove which macro applies.
34// Defining the macro directly in the crate root avoids this, because it is visible in all phases.
35//
36// # Documentation for declarative macros
37//
38// - [The Little Book of Rust Macros](https://veykril.github.io/tlborm/decl-macros.html)
39// - [Macros By Example](https://doc.rust-lang.org/reference/macros-by-example.html)
40// - [Specification](https://doc.rust-lang.org/reference/macro-ambiguity.html)
41
