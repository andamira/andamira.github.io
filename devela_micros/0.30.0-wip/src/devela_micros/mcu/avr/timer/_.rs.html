6//!
7//! # Clocking
8//!
9//! A hardware timer is fundamentally a counter driven by a timer clock.
10//!
11//! ```text
12//! source clock
13//!      │
14//!      ▼
15//!  prescaler
16//!      │
17//!      ▼
18//!     tick
19//!      │
20//!      ▼
21//!   counter
22//! ```
23//!
24//! This shows the common internally clocked case.
25//! Some timers can instead count events from another clock source or input pin.
26//!
27//! A **prescaler** divides the source clock by a supported integer factor `N`:
28//!
29//! ```text
30//! timer_frequency = source_frequency / N
31//! tick_period     = N / source_frequency
32//! ```
33//!
34//! The available values of `N` are fixed by the hardware rather than chosen arbitrarily.
35//! On the ATmega328P, Timer0 and Timer1 support `1, 8, 64, 256, 1024`;
36//! Timer2 additionally provides `32` and `128`.
37//!
38//! For example, with a 16 MHz source clock and `N = 64`:
39//!
40//! ```text
41//! timer_frequency = 16_000_000 / 64 = 250_000 Hz
42//! tick_period     = 64 / 16_000_000 = 4 µs
43//! ```
44//!
45//! The **counter** changes automatically on timer ticks according to the
46//! selected counting mode; software does not normally increment it itself.
47//!
48//!
49//! # Counting modes
50//!
51//! In **normal mode**, the counter normally runs through its full numeric range:
52//!
53//! ```text
54//! 0 → 1 → 2 → ... → MAX → 0 → ...
55//! ```
56//!
57//! For an 8-bit timer, `MAX = 255`. For a 16-bit timer, `MAX = 65_535`.
58//!
59//! Some modes use a configurable **TOP** instead. TOP is the highest value reached
60//! in the current counting cycle; it does not have to equal MAX.
61//!
62//! In the **CTC** mode considered here, the counter counts upward
63//! from BOTTOM through TOP and then begins again from BOTTOM:
64//! ```text
65//! 0 → 1 → ... → TOP → 0 → ...
66//! ```
67//!
68//! A compare register such as `OCR0A` or `OCR1A` can provide TOP.
69//!
70//! The interval is:
71//!
72//! ```text
73//! ticks = TOP + 1
74//!
75//! period = prescaler × (TOP + 1) / source_clock
76//! ```
77//!
78//! The `+1` exists because counting from zero through TOP includes both endpoints.
79//!
80//! To choose TOP for a desired period:
81//!
82//! ```text
83//! counts = source_frequency × desired_period / N
84//! TOP    = counts - 1
85//! ```
86//!
87//! An exact period is possible only when `counts` is an integer that fits the
88//! counter's available TOP range. Otherwise another prescaler or the nearest
89//! representable TOP must be chosen, introducing timing error.
90//!
91//! The source clock need not be the CPU clock;
92//! available sources depend on the timer and device.
93//!
94//!
95//! # Output compare
96//!
97//! An output-compare unit continually compares the running counter against a
98//! configured value:
99//!
100//! ```text
101//! counter ───┐
102//!            ├── equal? ──→ compare-match event
103//! compare ───┘
104//! ```
105//!
106//! A compare match can:
107//!
108//! * set an event flag;
109//! * request an interrupt when enabled;
110//! * affect a hardware output pin when configured to do so.
111//!
112//! CTC is one use of output compare: a compare value also becomes the end of the counting cycle.
113//!
114//!
115//! # Input capture
116//!
117//! Input capture solves the opposite problem.
118//!
119//! Output compare asks:
120//!
121//! > Has the counter reached this value?
122//!
123//! Input capture asks:
124//!
125//! > What was the counter value when this capture event happened?
126//!
127//! ```text
128//! counter keeps running
129//!         │
130//!         │       edge on capture input
131//!         │               │
132//!         ▼               ▼
133//! ... 12343 12344 12345 12346 ...
134//!                     │
135//!                     └── copied into capture register
136//! ```
137//!
138//! When the configured capture event occurs, hardware copies the current
139//! counter value into an **input-capture register** and sets an event flag.
140//!
141//! Software may read that value later. The captured value records when the edge
142//! occurred, rather than when software eventually noticed it.
143//!
144//! This is useful for measuring pulse widths, periods, frequencies, and event times.
145//!
146//!
147//! # Events, flags, polling, and interrupts
148//!
149//! A timer event is separate from how software reacts to it.
150//!
151//! ```text
152//! hardware event
153//!      │
154//!      ▼
155//!  event flag
156//!     ╱   ╲
157//! polling  interrupt
158//! ```
159//!
160//! With **polling**, software repeatedly checks the flag.
161//!
162//! With an **interrupt**, the peripheral's local interrupt enable
163//! and the CPU's global interrupt enable allow the event to invoke an ISR.
164//!
165//! The underlying timer event is the same.
166//!
167//!
168//! # PWM
169//!
170//! Pulse-width modulation repeatedly changes an output
171//! according to the timer's counting cycle and a compare point.
172//!
173//! In fast PWM, the counter repeatedly counts from BOTTOM through TOP:
174//!
175//! ```text
176//! BOTTOM ───────── compare ───────── TOP
177//!    │                │               │
178//!    └──── high ──────┴──── low ──────┘
179//! ```
180//!
181//! In a non-inverting output, the pin is set at BOTTOM and cleared
182//! on compare match. TOP therefore determines the PWM period,
183//! while the compare value determines the pulse width.
184//!
185//! ```text
186//! frequency = source_frequency / (prescaler × (TOP + 1))
187//! ```
188//!
189//! PWM output is generated directly by the timer hardware; software only
190//! configures the counting mode, compare value, and output connection.
191//!
192//!
193//! # Asynchronous clocking
194//!
195//! Some timers can run from a clock independent of the CPU clock.
196//! ATmega328P Timer2 can use a separate 32.768 kHz oscillator, allowing
197//! it to continue as an independent timebase while synchronous clocks stop.
198//!
199//! Register writes that cross between clock domains do not take effect
200//! immediately. Hardware exposes update-busy flags so software can wait
201//! until the timer has received the new values.
202//!
203//!
204//! # Choosing a timer operation
205//!
206//! Use **normal/free-running counting** when continuous elapsed ticks are useful.
207//!
208//! Use **output compare** when something should happen at a known counter value.
209//!
210//! Use **CTC** when a compare value should also define a repeating counting interval.
211//!
212//! Use **input capture** when the hardware should timestamp an external edge precisely.
213//!
214//! Use **PWM** when the timer should generate a periodic waveform with a controlled duty cycle.
215//!
216//! Use **polling** when the program can conveniently wait for an event.
217//!
218//! Use **interrupts** when other work should continue while the timer runs.
219//!
220//!
221//! # AVR-specific mechanics
222//!
223//! The concepts above are more general than AVR.
224//!
225//! Classic AVR devices realize these facilities through registers such as
226//! `TCNTn`, `OCRnA/B`, `ICRn`, `TCCRnA/B`, `TIMSKn`, and `TIFRn`.
227//!
228//! On the ATmega328P, Timer1 is a 16-bit peripheral attached to an 8-bit CPU.
229//! Its logical 16-bit registers are therefore exposed as pairs of byte registers.
230//! Hardware provides a temporary high-byte register to coordinate many paired accesses.
231//!
232//! Those byte-ordering and latch rules are important when implementing the driver,
233//! but they are not part of the basic timer model itself.
234//!
235//!
236//! # Timer/counter vocabulary
237//!
238//! - **clock** — the signal or event stream from which timer ticks originate.
239//! - **prescaler** — divides an internal timer clock by one of the hardware-supported factors.
240//! - **tick** — one counter-clock event.
241//! - **counter** — the value advanced by timer ticks.
242//! - **BOTTOM** — the lowest value in the counting sequence, normally zero.
243//! - **MAX** — the largest value representable by the physical counter.
244//! - **TOP** — the highest value reached in the current counting mode.
245//! - **compare** — detects when the counter equals a configured compare value.
246//! - **compare match** — the event produced by a successful comparison.
247//! - **event flag** — a register bit recording that a hardware event occurred.
248//! - **overflow** — an event produced when the counter crosses
249//!   a mode-defined end of its counting range.
250//! - **CTC** — *Clear Timer on Compare Match*: a compare value supplies TOP,
251//!   and the timer starts again from BOTTOM after reaching it.
252//! - **PWM** — uses periodic counting and compare points to control output duty.
